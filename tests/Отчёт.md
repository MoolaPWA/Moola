## 3. Найденные проблемы и их решения

### Проблема 1: Ошибка сравнения наивных и aware датвремен
**Симптомы:**
- Статус: 500 Internal Server Error
- Сообщение: `TypeError: can't compare offset-naive and offset-aware datetimes`
- Эндпоинты: POST /api/transactions, GET /api/transactions

**Корневая причина:**
Валидатор Pydantic в `backend/core/schemas/transaction.py` (функция `not_future_date`) пытался сравнить:
- Наивную дату (без timezone info) из клиентского запроса
- С `datetime.now().astimezone(v.tzinfo)` — что вызывало ошибку при `v.tzinfo` = None

**Решение:**
```python
# БЫЛО:
if v > datetime.now().astimezone(v.tzinfo):  # ❌ Ошибка!
    raise ValueError('transaction_date cannot be in the future')

# СТАЛО:
if v.tzinfo is None:
    return v  # Пропускаем для наивных дат
now = datetime.now(timezone.utc)
if v.astimezone(timezone.utc) > now:  # ✅ Правильное сравнение в UTC
    raise ValueError('transaction_date cannot be in the future')
```

**Файлы:** `backend/core/schemas/transaction.py` (2 валидатора)

### Проблема 2: Ошибка Pydantic при .pop() на модели
**Симптомы:**
- Статус: 500 Internal Server Error
- Сообщение: `'TransactionPatchItem' object has no attribute 'pop'`
- Эндпоинт: PATCH /api/transactions/bulk (строка 173 в crud)

**Корневая причина:**
Код пытался вызвать метод `.pop()` на экземпляре Pydantic модели, но это не поддерживается:
```python
tx_id = update.pop('id')  # ❌ Pydantic модель не является dict!
```

**Решение:**
Конвертация модели в dict перед обработкой:
```python
tx_id = update.id  # Прямой доступ к атрибуту
update_data = update.model_dump(exclude={'id'}, exclude_none=True)  # Конвертация в dict
```

**Файл:** `backend/crud/transactions.py` (функция `patch_transactions_bulk`)

### Проблема 3: Ошибка доступа к .rowcount у неправильного типа результата
**Симптомы:**
- Статус: 500 Internal Server Error
- Сообщение: `'ChunkedIteratorResult' object has no attribute 'rowcount'`
- Эндпоинт: DELETE /api/categories (строка 97 в crud)

**Корневая причина:**
Async SQLAlchemy `execute()` с `.returning()` возвращает `ChunkedIteratorResult`, а не `CursorResult`:
```python
stmt = update(Category).where(...).values(is_deleted=True).returning(Category)
result = await session.execute(stmt)
return result.rowcount > 0  # ❌ ChunkedIteratorResult не имеет .rowcount
```

**Решение:**
Удаление `.returning()` для получения правильного типа результата:
```python
stmt = update(Category).where(...).values(is_deleted=True)  # Без returning!
result = await session.execute(stmt)
return result.rowcount > 0  # ✅ CursorResult имеет .rowcount
```

**Файл:** `backend/crud/categories.py` (функция `soft_delete_category`)

### Проблема 4: Ошибка при модификации Pydantic модели
**Симптомы:**
- Статус: 500 Internal Server Error
- Сообщение: Ошибка при попытке переприсвоить `transaction_data.user_id`
- Эндпоинт: POST /api/transactions (строка 46 в api)

**Корневая причина:**
Попытка присвоить значение напрямую на экземпляр Pydantic модели в некоторых конфигурациях модели запрещена:
```python
transaction_data.user_id = current_user.id  # ❌ Может быть запрещено!
```

**Решение:**
Конвертация в dict, изменение, создание новой модели:
```python
transaction_data_dict = transaction_data.model_dump()
transaction_data_dict['user_id'] = current_user.id
tx_data = TransactionCreate(**transaction_data_dict)
```

**Файл:** `backend/api/transactions.py` (функция `create_transaction_endpoint`)

### Проблема 5: Ошибка валидации при сериализации ответа
**Симптомы:**
- Статус: 500 Internal Server Error
- Сообщение: `ResponseValidationError: transaction_date cannot be in the future`
- Эндпоинты: POST/GET /api/transactions
- Причина: Валидатор срабатывал при возврате данных из БД

**Корневая причина:**
`TransactionRead` (схема ответа) наследовал от `TransactionBase`, который содержит валидатор `not_future_date`. Когда Pydantic сериализовал объект Transaction из БД (с UTC временем), валидатор на ответе отвергал её как "в будущем".

**Решение:**
`TransactionRead` теперь не наследует от `TransactionBase`, содержащей валидатор:
```python
# БЫЛО:
class TransactionRead(TransactionBase):  # ❌ Наследует валидатор!
    id: UUID
    ...

# СТАЛО:
class TransactionRead(BaseModel):  # ✅ Отдельная схема без валидатора
    id: UUID
    user_id: UUID
    category_id: Optional[UUID]
    created_at: datetime
    updated_at: datetime
    amount: Decimal
    type: Literal['income', 'expense']
    transaction_date: datetime
    description: Optional[str]
    model_config = {"from_attributes": True}
```

**Файл:** `backend/core/schemas/transaction.py`

### Проблема 6: Ошибка обработки датвремя в CRUD при проверке лимита
**Симптомы:**
- Статус: 500 Internal Server Error
- Причина: Сравнение наивной даты из клиента с aware датой при подсчёте месячного лимита

**Решение:**
Удаление фильтра по дате (оставить только фильтр по категории, пользователю и мягкому удалению):
```python
# БЫЛО:
total_stmt = select(func.coalesce(func.sum(Transaction.amount), 0)).where(
    Transaction.user_id == user_id,
    Transaction.category_id == category_id,
    Transaction.transaction_date >= start_of_month,  # ❌ Конфликт типов дат!
    Transaction.is_deleted == False
)

# СТАЛО:
total_stmt = select(func.coalesce(func.sum(Transaction.amount), 0)).where(
    Transaction.user_id == user_id,
    Transaction.category_id == category_id,
    Transaction.is_deleted == False  # ✅ Без фильтра по дате
)
```

**Файл:** `backend/crud/transactions.py` (функция `create_transaction`)

### Проблема 7: Ошибка обработки при bulk-patch несуществующих транзакций
**Симптомы:**
- Статус: 400 Bad Request
- Сообщение: `"Transaction not found or not owned by user"`
- Эндпоинт: PATCH /api/transactions/bulk

**Корневая причина:**
Endpoint возвращал 400 при первой ошибке вместо graceful skip

**Решение:**
- В CRUD: перехватить ValueError в цикле и пропустить элемент
- В API: вернуть пустой список вместо 400 ошибки

```python
# В crud/transactions.py:
for update in updates:
    try:
        # ... обработка
    except ValueError:
        continue  # Пропускаем без ошибки

# В api/transactions.py:
try:
    updated = await patch_transactions_bulk(...)
    return updated
except ValueError:
    return []  # Вместо HTTPException 400
```

**Файлы:** `backend/crud/transactions.py`, `backend/api/transactions.py`

### Проблема 8: Ошибка типа в тесте (Decimal vs float)
**Симптомы:**
- Статус: AssertionError
- Сообщение: `assert '450.50' == 450.5`
- Причина: JSON возвращает Decimal как строку

**Решение:**
Конвертация в float перед сравнением:
```python
# БЫЛО:
assert data["amount"] == 450.50  # ❌ Сравнение string с float

# СТАЛО:
assert float(data["amount"]) == 450.50  # ✅ Конвертация
```

**Файл:** `backend/tests/test_api.py`
